## 失败复现

修复前，`deepseek_compatibility_test.dart` 的 5 个回归测试全部失败，覆盖指定工具选择被拒绝、半截 ping 参数被接受、完整接口地址重复拼接、推理片段丢失以及本机消息往返丢失推理元数据。使用真实 HTTP 客户端实现和模拟响应，不是对真实 DeepSeek 账号的复测。

## 修复后证据

- 57 项直接相关测试通过：连接设置、DeepSeek 协议兼容、Agent 循环、协议解析、原生/Web 传输、内置计划补齐、本机会话存储。
- 新计划测试核对五天 24 个动作的组数、次数、力竭标记、单侧说明、替代动作和腹部附加说明；原生及 Web 仓库升级均保留当前训练日、周次、训练最大值、动作状态和实例版本，重复补齐不产生重复计划。
- 连续工具调用测试在遗漏 `reasoning_content` 时模拟返回 400；修复后首轮工具调用、续接回答和重新打开会话后的下一轮全部成功，且推理元数据不进入可见回答并经过密钥脱敏。
- 空流、截断工具调用及无效 ping 参数均不会将配置标记为工具可用。Web 转发请求带有 DeepSeek 续接字段，其他供应商保持原请求格式。
- 离线字体新增 38 个所需中文字形，原有字形全部保留；3 项字体资源/样式测试通过。合计 60 项测试通过。
- 针对改动的 12 个 Dart 源码和测试文件运行静态检查，无问题。
- `openspec validate add-shenshi-plan-and-fix-deepseek --strict` 通过。

腹部训练保留为计划说明中的可选安排，不是自动加入训练记录的第六天。没有擅自设置初始负重、递减比例或自动加重。

## 真实供应商验证边界

当前环境没有可用的 DeepSeek Key，因此没有向真实供应商发送付费测试请求。兼容性修复依据协议模拟和 [DeepSeek 官方推理模式说明](https://api-docs.deepseek.com/guides/thinking_mode/)，不能据此声称用户账号上的原始报错已经完成在线复测。
